This document contains everything needed to build FamJam from scratch: architecture, stack, database schema, API contract, frontend structure, and business logic.

## 4. Database Schema

All tables use PostgreSQL. Amounts are **whole dollars** (integers). Timestamps are `timestamptz`.

### `users`

```sql
id          text PRIMARY KEY          -- Clerk userId
email       text NOT NULL
first_name  text
last_name   text
is_admin    boolean NOT NULL DEFAULT false
is_managed  boolean NOT NULL DEFAULT false  -- organizer-created; cannot sign in
created_at  timestamptz NOT NULL DEFAULT now()
```

### `reunions`

```sql
id                  serial PRIMARY KEY
code                text NOT NULL UNIQUE           -- 7-char alphanumeric join code
name                text NOT NULL
start_date          text NOT NULL                  -- ISO date (YYYY-MM-DD)
end_date            text NOT NULL
payment_handle      text NOT NULL                  -- e.g. "@venmo-handle"
payment_url         text
registrations_open  boolean NOT NULL DEFAULT true
organizer_id        text NOT NULL REFERENCES users(id)
created_at          timestamptz NOT NULL DEFAULT now()
```

### `reunion_fees`

```sql
id                      serial PRIMARY KEY
reunion_id              integer NOT NULL REFERENCES reunions(id) ON DELETE CASCADE
label                   text NOT NULL
charge_type             fee_charge_type NOT NULL DEFAULT 'per_person'  -- ENUM: per_person | flat
is_optional             boolean NOT NULL DEFAULT false
amount                  integer NOT NULL           -- whole dollars
age_threshold           integer                    -- optional; split point
amount_under_threshold  integer                    -- charge for attendees under threshold
sort_order              integer NOT NULL DEFAULT 0
```

### `reunion_branches`

```sql
id          serial PRIMARY KEY
reunion_id  integer NOT NULL REFERENCES reunions(id) ON DELETE CASCADE
name        text NOT NULL
sort_order  integer NOT NULL DEFAULT 0
```

### `reunion_organizers`

```sql
id          serial PRIMARY KEY
reunion_id  integer NOT NULL REFERENCES reunions(id) ON DELETE CASCADE
user_id     text NOT NULL REFERENCES users(id)
roles       reunion_role[] NOT NULL DEFAULT '{}'
created_at  timestamptz NOT NULL DEFAULT now()
UNIQUE (reunion_id, user_id)
```

`reunion_role` ENUM values: `registration`, `announcements`, `schedule`, `branches`, `reports`, `power_user`

### `registrations`

```sql
id                      serial PRIMARY KEY
reunion_id              integer NOT NULL REFERENCES reunions(id) ON DELETE CASCADE
user_id                 text NOT NULL
branch_name             text NOT NULL
attendee_count          integer NOT NULL
payment_status          payment_status NOT NULL DEFAULT 'pending'  -- ENUM: pending | paid | waived
status                  registration_status NOT NULL DEFAULT 'active'  -- ENUM: active | cancelled
cancelled_at            timestamptz
cancellation_resolution cancellation_resolution          -- ENUM: refunded | donated_to_fund | no_payment
created_at              timestamptz NOT NULL DEFAULT now()
```

### `attendees`

```sql
id                   serial PRIMARY KEY
registration_id      integer NOT NULL  -- implicit FK to registrations
name                 text NOT NULL
shirt_size           shirt_size NOT NULL  -- ENUM: XS | S | M | L | XL | 2XL | 3XL
dietary_restrictions text
age                  integer            -- optional; used for age-tiered fees
checked_in_at        timestamptz        -- null = not checked in
```

`shirt_size` ENUM values: `XS`, `S`, `M`, `L`, `XL`, `2XL`, `3XL`

### `registration_fees`

```sql
id               serial PRIMARY KEY
registration_id  integer NOT NULL REFERENCES registrations(id) ON DELETE CASCADE
fee_id           integer NOT NULL REFERENCES reunion_fees(id) ON DELETE CASCADE
```

### `sponsorship_contributions`

```sql
id                  serial PRIMARY KEY
reunion_id          integer NOT NULL REFERENCES reunions(id) ON DELETE CASCADE
registration_id     integer REFERENCES registrations(id) ON DELETE SET NULL
contributor_user_id text
contributor_name    text
amount              integer NOT NULL
source              sponsorship_contribution_source NOT NULL  -- ENUM: registration | direct | cancellation
created_at          timestamptz NOT NULL DEFAULT now()
```

### `sponsorship_allocations`

```sql
id               serial PRIMARY KEY
reunion_id       integer NOT NULL REFERENCES reunions(id) ON DELETE CASCADE
registration_id  integer NOT NULL REFERENCES registrations(id) ON DELETE CASCADE
amount           integer NOT NULL
funded_from      sponsorship_allocation_funding NOT NULL  -- ENUM: fund | direct
sponsor_name     text
note             text
created_by       text NOT NULL
created_at       timestamptz NOT NULL DEFAULT now()
```

**Fund balance formula:**
```
balance = SUM(contributions.amount)
        - SUM(allocations.amount WHERE funded_from = 'fund')
```

### `announcements`



### `polls`


### `poll_options`

```sql
id        serial PRIMARY KEY

```

### `poll_votes`

```sql
id         serial PRIMARY KEY
poll_id    integer NOT NULL REFERENCES polls(id) ON DELETE CASCADE
option_id  integer NOT NULL REFERENCES poll_options(id) ON DELETE CASCADE
user_id    text NOT NULL REFERENCES users(id) ON DELETE CASCADE
```

### `app_settings` (single-row)

```sql

tester_emails            text[] NOT NULL DEFAULT '{}'
updated_at               timestamptz NOT NULL DEFAULT now()
```

### Middleware Summary

| Middleware | What it does |
|---|---|
| `attachAuth` | Optionally extracts Clerk userId; does not reject unauthenticated requests |
| `requireAuth` | Rejects 401 if not signed in; creates/upserts user record |
| `requireAdmin` | Rejects 403 unless `users.is_admin = true` |
| `requireManage` | Verifies the user is the reunion owner or a co-organizer with any role |
| `requireReunionPermission(role)` | Verifies the user holds the specific role (or is owner) |
| `requireReunionOwner` | Verifies the user is the reunion owner specifically |

## 6. Business Logic Details

### 6.1 Admin Bootstrap

```
GET /admin/setup-status → { setupDone: boolean }
GET /admin/setup (signed in) → if no admin exists, sets caller as admin
                              → if admin exists, returns 403
```

### 6.2 Lockdown Mode

When `signInsLocked = true`, `GET /me/access` returns a locked error for any user who is not:
- A platform admin
- A reunion owner or co-organizer
- On the `testerEmails` allowlist (case-insensitive)

The frontend uses this endpoint on every load to gate access.

### 6.3 Sponsorship Fund Balance

Calculated on every read; not stored. Must be computed inside a transaction when validating an allocation:

```sql
SELECT
  COALESCE(SUM(sc.amount), 0) AS total_contributions,
  COALESCE(SUM(sa.amount) FILTER (WHERE sa.funded_from = 'fund'), 0) AS total_fund_allocations
FROM sponsorship_contributions sc
LEFT JOIN sponsorship_allocations sa ON sa.reunion_id = sc.reunion_id
WHERE sc.reunion_id = :reunionId
```

An allocation is rejected if `amount > (total_contributions - total_fund_allocations)`.

### 6.4 Managed Accounts

Managed accounts use a synthetic email: `managed-{uuid}@managed.famjam.internal`. This prevents email-based Clerk lookups from matching them. The `isManaged` flag must be excluded from any lookup that joins on email.

### 6.5 Poll Vote Atomicity

The vote endpoint acquires a `SELECT … FOR UPDATE` lock on the poll row before:
1. Verifying the poll is open
2. Verifying the user is a checked-in member
3. Deleting existing votes for this user on this poll
4. Inserting new votes (must not exceed `maxVotesPerMember`)

All steps run in a single database transaction.

### 6.6 Fee Computation

```
totalFee = 0
for each fee in reunion.fees:
  if fee.chargeType == 'flat':
    if !fee.isOptional OR fee is in selectedFeeIds:
      totalFee += fee.amount
  if fee.chargeType == 'per_person':
    if !fee.isOptional OR fee is in selectedFeeIds:
      for each attendee:
        if fee.ageThreshold AND attendee.age IS NOT NULL AND attendee.age < fee.ageThreshold:
          totalFee += fee.amountUnderThreshold
        else:
          totalFee += fee.amount
```

This logic is mirrored in both the API server and the frontend (for the registration preview). **Keep them in parity.**

### 6.7 Co-organizer Server-Side Enforcement

Every organizer endpoint re-checks permissions server-side. The `requireManage` middleware:
1. Extracts `reunionId` from the path
2. Looks up the reunion; returns 404 if missing
3. Checks that the user is the reunion owner OR exists in `reunion_organizers` with any role
4. Attaches `req.managedReunion` for downstream handlers

`requireReunionPermission(role)` additionally checks that the user's `roles` array includes the required role (or they are the owner, who has all roles implicitly).

## 7. API Contract Workflow

The API contract lives in `lib/api-spec/openapi.yaml`. **Never hand-edit the generated files.**

1. Edit `lib/api-spec/openapi.yaml`
2. Run `pnpm --filter @workspace/api-spec run codegen`
   - Regenerates `lib/api-client-react/src/generated/` (Orval → TanStack Query hooks)
   - Regenerates `lib/api-zod/src/generated/` (Zod schemas)
3. Add the corresponding Express route in `artifacts/api-server/src/routes/`
4. All `timestamp` fields in the spec **must** use `format: date-time` to generate `zod.coerce.date()` (not bare `zod.string()`)

**Known gotcha:** An operation with both path params and query params causes Orval to emit two exports with the same name. Avoid mixing path and query params on the same endpoint.

## 12. Database Migrations

Migrations are hand-written SQL files in `lib/db/migrations/`. During development, `drizzle-kit push --force` applies schema changes directly.

When adding a column with `NOT NULL` to a table that already has rows:

1. Add the column as `NULLABLE`
2. Backfill existing rows
3. Add the `NOT NULL` constraint
4. Record this as a psql transaction in `lib/db/migrations/`

(Running `drizzle-kit push` alone will fail for these cases.)

## 15. Key Architectural Decisions

| Decision | Rationale |
|---|---|
| Contract-first API (OpenAPI → Orval) | Single source of truth; type-safe client hooks auto-generated; any drift is a build error |
| Whole-dollar integer amounts | Avoids floating-point rounding; reunion context doesn't need cents |
| ISO date strings for event dates | Avoids timezone drift across user browsers and the server |
| Managed accounts with synthetic emails | Allows organizers to register offline family members without Clerk identities |
| Server-side permission re-check on every route | Defense in depth; client-side gating is UX only |
| Ledger-based sponsorship fund | Auditable; balance is always derivable from the transaction log |
| `FOR UPDATE` lock on poll votes | Prevents double-vote race conditions under concurrent requests |
| Migrations in `lib/db/migrations/` (not drizzle-kit auto) | Allows backfill-then-tighten pattern for production-safe NOT NULL additions |
